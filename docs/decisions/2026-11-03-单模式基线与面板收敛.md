# 2026-11-03 · 回归口径收敛为单模式，应用删除能力开关

## 背景与决定

用户确认（2026-11-02 会话，grill-me 逐项确认）：应用目标是"给一张图，出干净图"，
文字识别与笔画补全是技术能力，不存在合理的关闭场景，不应作为用户开关存在。

据此决定：

1. **回归基线只保留一种模式**：桌面默认（`required_modes = ["desktop"]`）。
   桌面关闭补全（desktop_protected）随开关删除而消失；CLI 参数对齐桌面默认后
   不再作为独立回归模式，CLI 入口仅保留工程单测层面的检查。
2. 以后不存在"两种模式"的测试口径；跨模式探针（cross_mode_probes）并入
   桌面默认的固定保护样本。
3. 滑条（mask_alpha_min、close_px、lama_mask_dilate 等）保留为用户可选覆盖，
   默认"自动位"= 内部默认值，跨会话不记住用户改动；用户覆盖结果好坏自负，
   只做机制探针，不进图片效果回归。
4. `lama_context_margin`、`lama_tile_overlap` 从界面删除，沉为内部常量。
5. 内部机制字段 `Thresholds.watermark_recall_priority` 保留（实验对照与
   自动比较依赖），仅删除用户控制面。

## 基线衔接

- 旧封存（423 页 × 三模式 = 1,269 页次）原样保留、不追认、不投影为新口径成绩。
- 面板改动落地后，按 `./start.sh freeze-baseline` 重建单模式观察基线
  （423 页 × 一模式），随后 `./start.sh test-release` 放行。
- 在新基线建立前，日常 `check` 与旧三模式基线的比较会因 profiles 不一致被
  门禁拒绝（fail-closed），这是预期行为：口径变更后必须重建基线。
