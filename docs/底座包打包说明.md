# 去水印底座包打包说明（交接版）

> 读者：负责在打包容器/GPU 机器上打"底座包"的同事。
> 一句话：**底座包 = 不变的大件（模型 + 便携 Python 环境），只打一次；
> 主程序包 = 代码，GitHub Actions 每次自动打。两个 zip 解压到同一目录即可运行。**

## 1. 为什么分两层

| | 内容 | 大小 | 更新频率 | 谁打 |
|---|---|---|---|---|
| **底座包** | LaMa 修复模型、WeVisOne-VL-2B 权重、便携 Python + GPU 版 PyTorch | ~7-8GB | 几乎不变 | 你（本文档），一次 |
| **主程序包** | 去水印.exe 与程序代码 | ~500MB | 每次改代码 | GitHub Actions 自动 |

7-8GB 的东西每次改代码都重打、重传没有意义，所以拆开。收件人首次拿两个
zip 解压到同一目录；以后升级只发 500MB 的主程序包，解压覆盖即可。

## 2. 打包前提（在 RTX A6000 那台 Windows 机器上）

1. 项目仓库已克隆，且**开发环境能跑提示词功能**：
   `out/third_party/WeVisOne-VL/.venv` 存在（脚本从它读取依赖清单、
   复制它的基础 Python 做便携运行时，保证版本逐钉一致）；
2. `models/WeVisOne-VL-2B/` 权重已就位，`models/inpainting_lama_2025jan.onnx` 在；
3. 有网络（仅本次需要，pip 要下载约 4GB 的 GPU 版 PyTorch 及依赖）；
4. **不要用微软商店版 Python** 建的 venv（复制出来跑不了）；如果不确定，
   脚本会自己检查并报错提示。

## 3. 打包步骤（三条命令）

在项目根目录：

```
python tools/build_runtime_base.py --dry-run    :: 先看计划，确认路径都对
python tools/build_runtime_base.py              :: 正式打包（约 20-40 分钟）
```

脚本自动完成：复制模型 → 复制便携 Python → 安装与开发环境逐钉一致的
依赖（torch 走 cu124 GPU 源）→ 导入自检并打印显卡是否可用 → 生成
`dist_base/去水印底座_YYYYMMDD.zip`。

只想先组装目录检查、不压缩：加 `--skip-zip`。

## 4. 打完怎么交付

- zip 超过 2GB，GitHub Release 单文件传不下，用 7-Zip 分卷（脚本结束时会
  打印现成命令）：`7z a -v1900m 去水印底座_YYYYMMDD.7z 去水印底座_YYYYMMDD.zip`，
  得到几个 1.9GB 的分卷，收件人全部下载后解压第一个即可；
- 或者走公司网盘/内网共享，整包直接放。

## 5. 收件人怎么用

1. 解压底座包，得到 `去水印底座/` 目录；
2. 把主程序包（GitHub Actions 产物 `dewatermark-windows`）解压到**同一目录**
   （`去水印.exe` 与 `models/`、`wevisone_runtime/` 同级）；
3. 双击 `去水印.exe`：自动识别开箱即用；提示词定位首次使用等 1-2 分钟
   模型加载，之后每页几秒。

## 6. 常见问题

- **自检打印 CUDA 可用: False**：打包机上显卡驱动/CUDA 异常，打出来的包
  在别的机器上也可能只能 CPU 跑（很慢）。先修好打包机再重打。
- **pip 下载超时**：重跑脚本即可，pip 有缓存会续传。
- **以后升级了 WeVisOne 环境或想换模型**：重跑一次本脚本打新底座，
  旧底座目录整体替换。
- **主程序包单独解压能用吗**：不能，缺模型。必须落在底座上。
