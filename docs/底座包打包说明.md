# 去水印底座包打包说明（交接版）

> 读者：负责在打包容器/GPU 机器上打"底座包"的同事。
> 一句话：**主程序包（GitHub Actions 自动打）= 解压即用的完整自动识别工具；
> 底座包 = 提示词定位的全家桶（大模型 + 便携 Python 环境），只打一次，
> 只有需要提示词功能的机器才叠加。**

## 1. 为什么分两层

| | 内容 | 大小 | 更新频率 | 谁打 |
|---|---|---|---|---|
| **主程序包** | 去水印.exe、程序代码、依赖库、LaMa 修复模型、OCR | ~400MB | 每次改代码 | GitHub Actions 自动 |
| **底座包** | WeVisOne-VL-2B 权重、便携 Python + GPU 版 PyTorch、LaMa（冗余一份） | ~7-8GB | 几乎不变 | 你（本文档），一次 |

主程序包单独解压就能跑自动识别（2026-11-25 起 LaMa 已并入主程序包）；
提示词定位需要的大模型和 torch 环境太大（7GB+）且不变，单独成底座，
只打一次。收件人按需领取：

| 收件人 | 发什么 |
|---|---|
| 只用自动识别 | 主程序包一个 zip |
| 要提示词定位 | 主程序包 + 底座包，解压到同一位置自动合并 |

## 2. 打包前提（任意一台够力的 Windows 机器即可，不必须是 A6000 实测机）

唯一的硬要求：**这台机器完整跑过本项目，包括提示词模型**——即：

1. 项目仓库已克隆，且 `out/third_party/WeVisOne-VL/.venv` 开发环境在
   （脚本从它读取依赖清单、复制它的基础 Python 做便携运行时，版本逐钉一致）；
2. `models/WeVisOne-VL-2B/` 权重已就位，`models/inpainting_lama_2025jan.onnx` 在；
3. 有网络（仅本次需要，pip 要下载约 4GB 的 GPU 版 PyTorch 及依赖）；
4. **不要用微软商店版 Python** 建的 venv（复制出来跑不了）；脚本会自查并报错。

## 3. 打包步骤（三条命令）

在项目根目录：

```
python tools/build_runtime_base.py --dry-run    :: 先看计划，确认路径都对
python tools/build_runtime_base.py              :: 正式打包（约 20-40 分钟）
```

脚本自动完成：复制模型 → 复制便携 Python → 按开发环境 pip freeze 逐钉安装
依赖（本地 wheel 直装原 wheel 文件，editable/VCS 安装反查本地源码目录装
非 editable 版，普通 pin 走 PyPI，torch 家族普通 pin 才走 cu124 GPU 源）→
导入自检并打印显卡是否可用 → 生成 `dist_base/去水印底座_YYYYMMDD.zip`。

只想先组装目录检查、不压缩：加 `--skip-zip`。

## 4. 打完怎么放置与交付

**两个 zip 里装的是同一个文件夹名 `去水印/`**——这是特意设计的：

```
去水印底座_YYYYMMDD.zip 解压 →  去水印/┬ models/（两个模型）
                                      ├ wevisone_runtime/（便携环境）
主程序包 dewatermark-windows.zip →   去水印/├ 去水印.exe + _internal/
                                      └ ……解压到同一位置自动合并成一个目录
```

- **底座包**（7-8GB，一次就好）：超过 2GB 传不了 GitHub Release 单文件，
  用 7-Zip 分卷（脚本结束时会打印现成命令），或放公司网盘/内网共享。
  建议固定一个存放点并记下来，以后不用重打；
- **主程序包**（~500MB）：每次推代码后从 Actions 运行页底部下载，
  通过网盘/微信发给收件人即可；
- **自己留一份合并好的完整目录**在本机，方便验证和应急拷贝。

## 5. 收件人怎么用

- **只用自动识别**：解压主程序包 → 双击 `去水印.exe`，完事；
- **要提示词定位**：底座包、主程序包两个 zip 解压到**同一位置**（两个 zip
  里都是「去水印」文件夹，Windows 自动合并），双击 `去水印.exe`；提示词
  定位首次使用等 1-2 分钟模型加载，之后每页几秒；
- 以后升级：只拿新的主程序包，解压覆盖同一位置即可（模型环境不动）。

## 6. 常见问题

- **自检打印 CUDA 可用: False**：打包机上显卡驱动/CUDA 异常，打出来的包
  在别的机器上也可能只能 CPU 跑（很慢）。先修好打包机再重打。
- **pip 下载超时**：重跑脚本即可，pip 有缓存会续传。
- **freeze 里出现 `@ file:///...` 或 `-e git+...`**：脚本直装本地 wheel、
  反查 editable 的实际源码目录，不依赖原下载渠道（代理地址不可达也能打）；
  只有源码目录/wheel 文件被删才会报错，按提示恢复后重跑。
- **以后升级了 WeVisOne 环境或想换模型**：重跑一次本脚本打新底座，
  旧底座目录整体替换。
- **主程序包单独解压能用吗**：不能，缺模型。必须落在底座上。
