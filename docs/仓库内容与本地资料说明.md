# 仓库内容与本地资料说明

版本：V3.1，更新日期：2026-11-06。

## 仓库保留什么

- `wm/`：应用、检测修复流程及必要资源。
- `tests/`：工程测试，个人外部修图助手测试除外。
- `tools/`：通用维护、评测、报告生成与研究工具，个人助手和投标工具除外。
- `config/`：回归规则、预定门槛和退役样本记录。
- README、安装与资源说明、项目架构及长期处理流程。

工程测试与回归规则继续保存。移除报告不表示删除测试样本、改变质量门槛或证明算法更好。

## 什么只留本机

| 范围 | 内容 |
|---|---|
| `out/` | 测试报告、输入输出、日志、每轮实验、封存基线及清理记录 |
| `docs/` 中非明确允许的文件 | HTML 报告、样本图片、内部分析、历史记录与标注说明 |
| `proposal/`、`tools/build_tender_*` | 投标方案和生成材料 |
| `下一步优化任务.md`、`visualizations/` | 内部任务草案与个人讲解素材 |
| `tools/kimi_image_*`、`tests/test_kimi_image_tools.py` | 个人外部修图辅助工具、依赖和测试 |
| `.kimi-code/`、`.qoder/`、`.codex/`、`.claude/` | 个人 Agent 配置 |
| `.chart-data-*/`、`.regression-control/` | 本机图表快照与基线指针 |
| `.env`、`.env.*`、编辑器目录、缓存 | 本地配置和开发状态；无真实凭据的示例配置可入库 |
| `data/`、`models/`、`.venv/` | 数据、模型及本机运行环境，另行准备 |

文档允许清单以 `.gitignore` 的逐文件条目为准。除架构、处理流程和本文外，仓库还共享两份团队开发文档：

- [离线智能去水印：从零配置到启动](离线智能去水印从零配置到启动_20261106.html)
- [离线智能去水印：项目方向](离线智能去水印项目方向_20261106.html)

需要加入新的通用说明时，先审核内容，再显式调整 `.gitignore`，不要强制加入整个报告目录。

本地报告目录入口为 `out/水印验证报告总目录.html`。该文件及其引用资料只在拥有相应本地文件时可用，不作为克隆仓库后的必备入口。通用报告生成脚本仍可生成这些文件，忽略规则会阻止普通提交再次收录。

## 本次清理的边界

首次清理以普通提交取消追踪；随后按用户要求，对新仓库的全部分支和标签历史继续清理。报告、样本展示素材、内部计划及个人辅助文件从各历史树中移除，保留工具的旧版本也移除了个人字体绝对路径。代码开发提交及其先后关系继续保留，受影响的提交编号和新仓库资源标签指向会改变。

所有本地原件保留，清理前的分支与标签另有本地备份。清理在隔离目录中执行，不删除本机检查点、旧原件或历史封存；本地工作分支同步到新历史，不把旧历史合并或推回新仓库。

核对范围是新仓库所有分支、标签及重新克隆后可取得的完整历史。GitHub 服务器内部的未引用对象、旧提交地址缓存，以及其他人的旧克隆副本不受本机 Git 操作控制，不能据此宣称这些副本已经物理擦除。平台侧限制见 [GitHub 历史清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

原仓库和原 Release 保留。2026-11-02 已通过独立 Release 操作，将六个原始附件复制到 [新仓库资源 Release](https://github.com/RedCreationTech/offline-dewatermark/releases/tag/resources-2026-10-27)，并更新当前下载入口。附件文件名、大小、SHA256 和原始快照内容保持不变；Release 说明补充历史清理后的标签映射及当前报告边界，不把旧包当成当前完整清单。

本机 `refs/codex/` 检查点没有推送到新仓库。新仓库历史清理也不删除这些本地检查点；不要对包含本机内部引用的工作仓库执行镜像推送。

其他机器若已有新仓库的旧克隆，优先重新克隆；不要直接合并旧历史再推送，否则可能把清理过的资料带回。原仓库的历史仍按用户要求保留，不应推回新仓库。

## 本地备份与质量口径

换电脑时另行备份所需数据、模型、输入导出、完整封存结果及方案原件；密钥和个人配置单独管理。本机绝对路径不应写进共享工具，语料和报告字体分别用 `WM_CORPUS_FONT`、`WM_REPORT_FONT` 显式指定。

本次没有调整检测、修复、路由、参数、样本或基线。逐张及跨样式效果不在本次重新测量；未完成完整发布放行与独立泛化验证，仓库清理不构成效果提升或质量合格的证据。
