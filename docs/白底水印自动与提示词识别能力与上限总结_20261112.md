## 2. 样本与真值

- 输入：`out/斜向平铺_白底_缩小906×1280_20261111_135849/` 顶层 13 张 PNG（s000–s012），906×1280。
- 来源：由全分辨率 1654×2338（`out/斜向平铺_白底_20261110/斜向平铺_白底/`）经 Pillow **LANCZOS** 缩放派生；alpha 以 float32 同缩放并裁至 [0,1]。缩放派生真值不等同重新合成的精确真值。
- 分组：透明度组（极淡12/基准30/中50/浓70）、颜色组（基准灰/深黑/红/蓝/浅黄）、尺寸组（小字28/小字40/基准56/大字80）。斜向 -35°、stagger 0.5 平铺。
- 真值：同目录 `*_gt.npz`（clean/alpha/color/strength），**仅供推理完成后事后评估**，不进入应用输入。`dataset.json` 记录输入/底图 sha256、像素字号与间距，可用于校验复现输入一致。
- 字号实测：906 宽下 s009 字符连通域中位高约 **12px**；s010（小字40）可检、s009（小字28）不可检，构成字号下限边界。

## 3. 复现命令（同口径重跑）

GUI 默认参数（`tools/run_dev_batch.py` 内置）：`mask_alpha_min=0.08`、`lama_context_margin=256`、`lama_tile_overlap=64`、`lama_mask_dilate=0`、`watermark_recall_priority=True`、`close_px=11`、`use_ocr=True`、dpi=200。

```bash
SRC="out/斜向平铺_白底_缩小906×1280_20261111_135849"
# 自动识别一轮
QT_QPA_PLATFORM=offscreen HF_HUB_OFFLINE=1 .venv/Scripts/python.exe tools/run_dev_batch.py \
  --input-dir "$SRC" --out "$SRC/自动识别复现_<ts>" --mode auto
# 提示词识别一轮（逐页启停模型服务，8G 显存防跨页 OOM）
QT_QPA_PLATFORM=offscreen HF_HUB_OFFLINE=1 .venv/Scripts/python.exe tools/run_dev_batch.py \
  --input-dir "$SRC" --out "$SRC/提示词复现_<ts>" --mode prompt --prompt "内部资料 08812 2026-11-10"
# 事后评估 + 自包含报告（真值仅在推理后加载）
.venv/Scripts/python.exe tools/build_dev_batch_report.py --run-dir "$SRC/<轮目录>" \
  --dataset-json "$SRC/dataset.json" --gt-dir "$SRC" --out "$SRC/<轮目录>/报告.html"
# 回归（自动模式不受提示词门禁影响）
.venv/Scripts/python.exe -m unittest discover -s tests
QT_QPA_PLATFORM=offscreen HF_HUB_OFFLINE=1 .venv/Scripts/python.exe tools/run_min_regression.py --suite all
```

- 提示词模式在 8G 显存下**必须逐页启停服务**（`run_dev_batch.py` 已内置）；常驻跨页累积会 OOM。
- 确定性：同代码＋同模型＋同输入 → 同掩码。实测提示词三轮与四轮 12 张成功页掩码**逐字节一致**，可作复现校验。
- 每轮用**新输出目录**，不覆盖旧轮；`run.json` 保存输入哈希、阈值、模式、code_snapshot、LaMa sha，供追溯。

## 5. 去除上限与已知边界（8G 显存・906×1280）

1. **字号下限**：字符高 ≲12px（s009 小字28）自动识别召回 0、提示词 VLM 要么 OOM 要么低召回；小字40（s010）可检。降分辨率会进一步压低字号，不可取（见 6）。
2. **显存上限**：WeVisOne-VL-2B 在 8G 卡上对**密集小字页**（s009）峰值超 8G → CUDA OOM（尝试再分配 6.75GiB、可用 0）。其余 12 张可跑。需逐页启停服务；s009 单页新鲜服务仍 OOM，属该图资源上限。
3. **极淡透明度**：s000（12%）α>0 全量召回仅 ~51–52%（淡抗锯齿边缘漏），但强召回 ~98% → 可见笔画基本可除，淡边缘召回存在上限；不能用提高阈值缩小分母冒充改善。
4. **低对比彩色**：浅黄（s008）α>0 召回 53–73%、强 93–98%；红/蓝提示词 α>0 召回偏低（57–59%）但强 100%、误差 0 → 淡边缘口径与可见笔画口径需分开看。
5. **过选保护闸门**：选区占页 >25% 判"重绘范围过宽"→保留原图、needs_manual_mask。低分辨率过选实验即触发此闸门（见 6）。
6. **白底门禁**：纸面直填与边带/笔画证据补全仅对"近白纸面为主且无正文墨迹"页启用；有正文页保留 LaMa 与正文保护，不适用本表数字。
7. **口径区分**：召回(α>0)、强召回(α≥0.5)、精确率、选区覆盖率、实际修改像素是不同概念，不可互换改善指标。

## 6. 负结果记录：s009 降分辨率实验（不可行）

- 条件：s009 原图 0.5× LANCZOS → 453×640（像素 1/4），仅用新代码提示词模式处理该图；真值保留原分辨率、评估时预测上采样对齐。
- 结果：**不再 OOM**（50.9s），但选区过宽——覆盖 45.7%、精确率 18.7%（掩码误选大量块状背景），触发 25% 闸门→保留原图、未通过、实际未修复；上采样后召回 70.7%、强召回 49.7%；字号进一步缩到 ~6px。
- 结论：降分辨率以"过选＋字号更小"换显存余量，**不是 s009 的可行修复**。过选诱因符合固定像素尺度形态学/闭运算（close_px=11）在低分辨率下相对字号过大而连块（掩码形态支持；精确触发点未单独隔离）。
- 复现：先 LANCZOS 0.5× 生成输入与同名 `_gt.npz`（原分辨率），再按第 3 节提示词命令单页运行。
- 正确方向（未实施）：压显存峰值但**不缩字号**（限制候选区域数/分块送模型/更大显存），会改变提示词输入口径，需另开任务并回归。
