# 「按提示词找水印并去除」功能设计（定稿 V1.0）

- 日期：2026-11-07
- 状态：定稿（grill-me 质询完成，全部问题已达成共识；待用户人工查验后开工）
- 依据：WeVisOne 提示词分割实验（`out/WeVisOne提示词分割实验报告_20261106.html`，单样本 core_009，5 组提示词对照）

## 1. 背景与目标

桌面工作台已有两条人工辅助通道：圈选找笔画（`assisted.find_strokes`）和笔刷编辑完整选区（`selection_edit.apply_selection`），它们对所有处理结果通用。

**找水印方式定位为三种并列手段**（用户已确认的产品方向）：

1. **自动识别**（现有）：`masks.estimate_single_page` 全图启发式检测；
2. **提示词定位**（本方案）：用户输入一句自然语言提示词（如"验证素材 3409"、"水印"），由本地 WeVisOne-VL-2B 模型给出水印实例的检测框，框内再走现有像素证据管线提取候选笔画；
3. **水印图片模板匹配**（暂不开发）。

无论哪种方式找到水印，都汇入同一条后续工作流：修复前证据闸门 → 修复（透明度反解／LaMa 等路由）→ 质量判定 → 导出；去得不彻底时，画笔类辅助（圈选、笔刷）照常可用。WeVisOne 的 matte 不进候选选区，也不在界面显示（见 Q3）。

## 2. 现状梳理（GUI 全部实现）

### 2.1 模块职责

| 模块 | 职责 |
|---|---|
| `wm/app.py`（1289 行） | `MainWindow`：批次/页面列表、参数面板（5 个滑杆＋OCR 开关＋补全开关＋样式框）、四视图预览、辅助操作条（编辑选区/按当前选区处理/取消/撤销）、批量队列启停、导出 |
| `wm/batches.py` | `Batch`（pages/results/states/dirty/params/use_ocr/style/priors）与 `BatchWorker`（QThread 逐页队列：结构探测→跨页先验→单图检测→修复→判定，可暂停/停止） |
| `wm/pipeline.py` | 批处理与流式入口；`_process_one` 做修复前证据闸门（`_gate_block_reason`：空选区/低置信/修复面过大→原样输出并标记人工复核）＋修复＋判定 |
| `wm/assisted.py` | 圈选找笔画：`find_strokes(result, rectangle, ...)` 在圈定 crop 上跑 `masks.estimate_single_page` 得局部 alpha，再用 `recall._pixel_strokes` 按颜色/局部对比过滤出"有当前图证据的笔画"，`StrokeProposal` 记录矩形、图层、哈希；`apply_proposal` 校验图片未变、选区哈希未变、改动不超出预览范围后修复 |
| `wm/selection_edit.py` | 笔刷增删完整选区，`SelectionEdit` 每笔补丁历史；`apply_selection` 从**原图**按完整选区重修复（不是迭代修输出），人工笔画走 LaMa，自动保留部分走原路径；选区语义是"修复许可"不是物理透明度 |
| `wm/contract.py` | `MaskLayer`（alpha/footprint/selection/repair_mode/method…）、`Thresholds`、`PageResult`、`VerdictReport`；`selection` 字段＝显式修复许可 |
| `wm/masks.py` | `estimate_single_page`（单图检测，style/close_px/ocr 参数）、`estimate_crosspage`（同尺寸组跨页先验）、`with_prior` |
| `wm/viewer.py` | 画布：搜索圈选矩形（`rectangleFinished`）、笔刷、选区叠加、放大镜 |
| `wm/assist_worker.py` | `AssistWorker`（QThread）统一跑 find/apply/selection 三种辅助动作，完成后回主线程 |
| `wm/styles.py` | 中文样式提示词→样式代码（`parse_style_prompt`），与检测路由正交 |

### 2.2 圈选辅助的精确机制（新功能的接入范本）

1. 用户在已有自动结果的画布上拖出搜索矩形 → `find_assisted_strokes` → `AssistWorker('find', result, rectangle, thr, close_px, use_ocr, style)`。
2. `find_strokes`：矩形外扩 64px 取 crop → `estimate_single_page(crop)` → 圈内的种子像素必须再过 `recall._pixel_strokes`（颜色/局部对比证据）→ 候选笔画；`lama_mask_dilate` 强制为 0。
3. 预览：红色候选笔画叠加在**当前输出**上，黄框仅为搜索范围；图片未变。
4. 确认 → `AssistWorker('apply', result, proposal)` → `apply_proposal` 三重校验（原图哈希、选区哈希、改动⊆选中⊆矩形）→ 修复 → 新判定 → 撤销栈、批次状态、导出保留自动基线。
5. 全程在输出图上操作（修残留），不从原图重跑检测；PDF 结构引擎页不适用（同圈选）。

### 2.3 已有实证基础（WeVisOne 实验边界）

- 检测框定位准、能给出全部实例（底行裁切实例对弱提示词会漏）。
- matte 沿字形但系统性偏粗：精确率约 52%，**不能直接当修复掩码**。
- 单页推理 16–22s（1152×864，RTX 3060 Ti，bf16，`decoder_batch=4`）；每进程冷启动加载模型另需约 15–25s。
- 模型在独立 venv：`out/third_party/WeVisOne-VL/.venv`（主 venv 无 torch）；模型权重 `models/WeVisOne-VL-2B`。

## 3. 方案设计

### 3.1 进程模型（已评审）

主 venv 没有 torch，必须用 WeVisOne venv 起独立推理进程。**已达成共识：页面以「找水印方式」下拉作为功能开关**，批次级参数（方案 A）；只有方式＝提示词定位时才显示提示词相关控件（服务方式＋提示词输入框），水印样式反之隐藏（见 3.2b）。服务生命周期绑定方式选择：

- **常驻模式**：选中"常驻服务"即异步预热（模型常驻显存）；切回"自动识别"或退出程序即停掉服务、释放显存。显存占用由用户显式掌控，避免长期占 6–7GB 影响其他 GPU 用途。
- **按需模式**：每轮处理启动一次、该轮全部页面跑完即停；适合显存紧张或偶尔使用的用户。
- 进程崩溃兜底：常驻模式下若服务意外退出，下次调用自动重启一次；重启失败则报错并回到未启用状态。
- **启停时机（已确认）**：常驻服务＝选中"常驻服务"即异步预热（状态栏显示"提示词模型启动中…"），切回"自动识别"或退出程序即停、释放显存；按需启动＝每轮处理启动一次、该轮全部页面跑完即停（不按页重启）。
- 服务脚本落在 `tools/`（如 `tools/wevisone_server.py`，用 WeVisOne venv 的 python 运行），请求 `{image_base64, query}` → 响应 `{instances: [{box, matte_base64}], latency_ms, model_path}`；超时/环境缺失时 GUI 优雅降级（功能不可启用或本次调用报错，图片不变）。

### 3.2 功能接入（提示词＝批次级检测方式，入口形态已定为方案 A）

- **入口与参数**：参数面板按「找水印 → 去水印 → 修复底图」重排分组（布局见 3.2b）；「找水印」组内新增「找水印方式」下拉（自动识别 / 提示词定位）——该下拉即功能开关：方式＝提示词定位时显示服务方式（常驻/按需）与提示词输入框，方式＝自动识别时显示水印样式；方式与提示词随批次持久化（同 `style` 的存法）。
- **批量流程**：`BatchWorker` 逐页跑到栅格检测时，若该批次选了提示词方式：调 WeVisOne 服务（当前页原图＋提示词）→ 得若干实例框 → 对每个框外扩 64px 取 crop，复用圈选的提取管线（`estimate_single_page(crop)` → `recall._pixel_strokes` 证据过滤）→ 各框候选笔画并集组成 `MaskLayer`（`source=MODEL`，`method='prompt_located_strokes'`，alpha 取框内局部检测值、框外为 0；可反解字段按框保留，否则降级 `inpaint`）→ 汇入统一的闸门→修复→判定。
- **结构引擎优先**：PDF 透明文字对象探测仍在最前（提示词方式只作用于栅格路径）；跨页先验在提示词模式下不适用（各页框不同），按单页处理。
- **空手与兜底**：模型返回 0 实例、或证据过滤后候选为空 → 闸门 `empty_selection` 拦截，该页原样输出并标记需人工处理；模型服务失败 → 该页记"运行失败"，队列继续。
- **后续通用**：提示词方式产出的就是普通 `PageResult`（非人工辅助），圈选/笔刷辅助、撤销、导出保留基线等机制原样可用。
- **结果可视化（A＋B 已确认）**：流程不加人工环节；每张处理完的图在「水印选区」视图显示最终选区红叠加（两种方式一致），提示词模式额外以黄框叠加模型给出的实例框（存入 `MaskLayer.instances`，复用画布圈选黄框绘制），用户可对照"模型找了哪些位置"与"实际选中哪些笔画"；matte 不显示。空手时状态栏给出可诊断信息（"模型给出 N 个框，框内未找到足够证据的笔画"），框坐标同步写入 `processing` 与导出证据。
- **辅助动作复用**：`apply_proposal` 保持单矩形语义不变（圈选场景不动）；提示词路径的多框合并在新的检测构建器里完成，不走 `apply_proposal`。

### 3.2b 参数面板布局（按 找水印 → 去水印 → 修复底图 重排）

仅调整分组与顺序，参数含义、stage 标记、失效重算逻辑全部不变。方式相关控件**条件显示**：只有该方式用到的参数才出现。

**找水印**（检测阶段）
1. 找水印方式：自动识别 / 提示词定位（下拉，随批次保存）
2. ——仅当方式＝提示词定位时显示——
   - 服务方式：常驻服务 / 按需启动（二选一）
   - 提示词输入框（随批次保存）
3. ——仅当方式＝自动识别时显示——
   - 水印样式（下拉）
4. 共有参数（两种方式都使用）：
   - 文字识别（勾选）
   - 补全水印笔画（勾选；自动比较试用版下保持现有替换文案）
   - 水印笔画连接（滑杆，close_px）
   - 水印判定阈值（滑杆，mask_alpha_min）

**去水印**（移除范围）
- 水印选区外扩（滑杆，lama_mask_dilate）

**修复底图**（LaMa 修复）
- 修复参考范围（滑杆，lama_context_margin）
- 修复分块重叠（滑杆，lama_tile_overlap）

底部按钮维持：处理／重处理当前图片、恢复默认、重新自动识别当前图片。

与现行界面的差异说明：滑杆按工作顺序重排（检测两项从末尾提到「找水印」组）；「去水印」组第一版只有外扩一个参数——移除阶段用户可控项本来就少；样式框在提示词模式下隐藏（替代原"变灰"方案，更省视觉噪音）。

### 3.3 明确不做（第一版）

- 不做"水印图片模板匹配"（第三种找水印方式，后续单独立项）。
- 不做候选来自 matte 阈值化的路径（违反"新增选中像素必须有像素证据"的边界）。
- 提示词检测不接入跨页先验，不做无证据的全图外推填框。
- 不在提示词模式下跳过 PDF 结构引擎探测（结构对象移除仍优先）。

### 3.4 环境缺失与降级

WeVisOne venv 不存在 → 提示词方式不可选（或选中后给出指向配置文档的明确提示）；进程启动失败/推理超时 → 状态栏报错，不残留半成品状态；模型路径默认 `models/WeVisOne-VL-2B`，可用环境变量 `WM_WEVISONE_MODEL` 覆盖（将来换 4B 不用改代码）。

## 4. 边界与防退化约束（AGENTS.md 对齐）

- 检测框/matte 只作搜索范围与目视参考，最终选区必须来自当前图的颜色/局部对比等像素证据；圈选辅助的"预览范围＝修复许可范围"语义保持不变。
- 提示词方式为批次级显式选择，默认仍是自动识别，不改变自动检测、修复、路由行为；负例（如 core_023 无水印）不得因提示词产生选区或改动。
- 接入默认路径前需：开发样本（core_009 等 tiled 类）对照、固定最小回归、无水印负例、另外两种模式探针；缺独立验证则保持辅助实验状态，不宣称通用提升。
- 行为落地后同步更新 `docs/去水印处理流程图.md`（版本与日期）。

## 5. 验收口径（分层）

1. 单元测试：空候选闸门拦截、服务进程超时/崩溃/环境缺失降级、MaskLayer 构建（框外 alpha 为 0、可反解字段按框保留与降级）、批次参数持久化。
2. 开发样本：core_009 上"提示词检测"与"自动检测"逐实例对照（含弱提示词如实记录）；负例 core_023 在提示词模式下零选区零改动。
3. 回归：`./start.sh test --plan` 定层后跑对应层；固定集诊断入口对照；负例零改动。
4. 报告：复用 `tools/build_wevisone_prompt_report.py` 的模式产出对照报告并挂总目录。
