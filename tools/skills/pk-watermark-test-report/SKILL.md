# PK 赛去水印批次测试报告（固定评定规程）

## 安装到其他电脑（本文件随仓库同步，是权威副本）

1. 把本文件夹（`pk-watermark-test-report/`）整体复制到目标机器的用户技能目录：
   `C:\Users\<用户名>\.kimi-code\skills\pk-watermark-test-report\`
   （Kimi Code 启动后自动识别为技能；目录里 SKILL.md / build_pk_report.py / run_config.example.json 三个文件都要在。）
2. 不安装也可以直接当脚本用：见下方「生成报告」命令，用仓库内路径调用即可。
3. 修改评定口径或模板时，只改仓库副本（本文件与脚本），再重新复制到各机器的用户技能目录，避免多副本漂移。

## 适用场景

用户在 `D:\gaocunbin\pk-test\去水印`（打包应用）里跑完一个批次并「导出结果」后，按本规程出报告。
每次测试一个**新的时间戳子目录**（`D:\gaocunbin\pk-test\test\YYYYmmdd_HHMMSS\`），历史子目录保留作轮次对照。

## 评比指标（源自 D:\gaocunbin\pk-test\离线去水印的评比要求.docx，勿自行改动公式）

- **水印去除速度（35 分）**：记录批处理总时间 T（秒）与文档数 N，T/N≤120 时得分 = (120−T/N)/6+15，超过 120 不得分。
- **水印去除成功率（35 分）**：成功规则原文「去除后文档整体风格不变、水印区域不影响内容识别、非水印区域与原文保持一致」；得分 = A/B×35。
- **总成绩 = 两项之和（70 分）**。

### 固定口径（每轮必须一致）

- **主口径（从严）**：任何可见水印残留、或任何非水印内容被改动（含交叠带造字导致的错字）→ 该页不通过；仅小墨点/淡痕且内容可识读 →「成功（有瑕疵）」计入 A，瑕疵必须逐页披露。
- **宽松口径**：水印基本去除、文档整体可正常使用即计入 A。报告中必须同时给出两种口径的得分，主口径放首位，注明「最终以裁判判定为准」。
- **T 的取值**：用应用状态栏「批次总用时」（队列墙钟），与 manifest 逐页 elapsed 合计互证；两者差异>5% 时要在报告里说明。

## 每次评定规程（按顺序执行）

1. **前置核验（必做）**
   - 读 `D:\gaocunbin\pk-test\去水印\logs\wm.log`：必须出现「OCR 引擎已就绪」；若只有「初始化失败」警告，先停——这是打包缺依赖事故（2026-11-26 曾发生），不能出正常报告。
   - 记录被测包版本/构建提交、本机硬件（注明竞赛指定平台为 RTX A6000，成绩不可跨硬件等同）。
2. **数据核对**：导出目录下 manifest.json / queue.json / 逐页 PNG 齐全；输入图片与导出 source 逐像素一致（抽查即可）。
3. **指标表**：从 manifest 提取每页 置信度/选区px/覆盖率/修复方式/闸门/失败码/耗时分解（模型服务 ms 在 processing.prompt_detection.service_ms）。
4. **像素三查（每页，用脚本）**：改动像素数、选区外改动（必须=0）、选区均色（原→出）。
5. **逐张目视（必做，不可只看指标）**：每页看整页输出 + 水印区放大（1700×2200 图用 crop (500,700,1150,1450)）。重点故障模式：水印大面积残留（淡笔画漏选）、交叠带造字（LaMa 重建小字错字）、正文误白、小墨点/淡痕。
6. **写判定**：按固定口径给每页 ok/bad + 一句依据（瑕疵要写清位置与程度）。
7. **生成报告**：填 `run_config.json`（模板见 `run_config.example.json`），然后在仓库根目录执行：

```bash
.venv/Scripts/python.exe tools/skills/pk-watermark-test-report/build_pk_report.py --config <当轮config.json>
```

（任何带 numpy、PIL 的 Python 都可以；仓库 .venv 只是最方便的选择。）

8. **对照**：报告含与上一轮同口径得分对照表；每轮保留子目录，不覆盖。

## 报告要求（脚本已固化）

- 自包含 HTML（图片 base64 内嵌，最长边 800、JPEG），标题带生成日期时间（精确到分钟）。
- 结构：本轮成绩速览 → 口径说明 → 测试对象与口径 → 科目一速度 → 科目二成功率（含逐页判定表）→ 逐张证据（原图/选区/输出/放大）→ 轮次对照 → 问题与优化方向 → 局限。
- 术语用 ❓ 浮层（词表在脚本 GLOSSARY 内）。
- 子目录里同时归档 manifest.json 与 queue.json 供核验。

## 已知坑（每轮对照排查）

- OCR 静默失效 → 批量质量塌缩（查日志「OCR 引擎」行）。
- 有正文页 text_keepout 非空 → 修复走 LaMa（慢、交叠小字易造字）；白底无正文页走纸面直填。
- complete_prompt_strokes 在有正文页整体停用 → 淡水印边带残笔漏选（残留主因之一）。
- LaMa 在本机走 CPU（RTX 3060 Ti 环境）；竞赛机 A6000 的速度数字需现场复测。
